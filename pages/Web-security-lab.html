Web Security Lab

Practice identifying common web security weaknesses in safe, controlled learning scenarios.

Lab 1: Identify Secure HTTPS

Challenge

A website uses HTTPS instead of HTTP. What is one important benefit of HTTPS?

Answer: HTTPS helps protect communication between the browser and server by encrypting the connection through TLS.

Lab 2: Authentication

Challenge

A web application allows users to log in with only a username and a password. What additional control could improve account security?

Answer: Multi-factor authentication can provide an additional verification factor.

Lab 3: Input Validation

Challenge

A web application accepts information from users. Why should the application validate and safely handle that input?

Answer: Proper input validation helps prevent unexpected or unsafe data from being processed in dangerous ways.

Lab 4: Access Control

Challenge

A normal user attempts to access an administrative function that should only be available to authorized administrators.

What security control should prevent this?

Answer: Proper authorization and access-control checks should prevent unauthorized users from accessing restricted functionality.

Lab 5: Security Misconfiguration

Challenge

A web server exposes unnecessary services and uses insecure default settings.

What should a security professional recommend?

Answer: Remove unnecessary services, change insecure defaults, apply appropriate security configurations, and keep the system updated.

Lab 6: Session Security

Challenge

A web application uses session cookies to keep users logged in. Why should session identifiers be protected?

Answer: Unauthorized access to a valid session identifier could allow someone to impersonate the associated session.

Lab 7: Security Review

Challenge

During an authorized security review, you discover a possible weakness. What should you do before attempting further testing?

Answer: Confirm that the activity is within the approved scope and follow the rules of engagement.

Lab Rules

  • Use only authorized laboratory environments.
  • Do not test real websites without permission.
  • Do not collect or expose real users' information.
  • Follow the scope and rules of each exercise.
  • Document findings responsibly.
